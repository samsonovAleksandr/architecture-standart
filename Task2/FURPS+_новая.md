| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | **Функциональные (Functionality)**     |              |
|     |Сайт и интернет-банк показывают доступные депозиты с актуальными ставками; интернет-банк дополнительно показывает персональные ставки. Ставки ведутся централизованно и доступны уполномоченным сотрудникам депозитного и кредитного бэк-офиса.                               |              |
|     | Клиент сайта подаёт заявку с Ф. И. О. и телефоном. Заявка поступает в систему кол-центра для звонка и предложения условий; новый клиент проходит идентификацию в отделении.
|              |В интернет-банке клиент выбирает счёт и сумму и подтверждает заявку СМС-кодом. Менеджер бэк-офиса обрабатывает её и подтверждает условия в АБС. Клиент получает СМС после согласования ставки и после открытия депозита.
| U   | **Удобство использования (Usability)** |              |
|     | Интерфейсы должны соответствовать дизайн-системе банка: использовать привычные цвета, компоненты и брендированные элементы.                                |              |
|     | Клиент должен получать понятное подтверждение приёма заявки и информацию о дальнейших действиях, включая звонок и визит в отделение для нового клиента.                               | Дополнительное требование: в MVP заявку обрабатывает сотрудник, поэтому интерфейс не должен создавать впечатление, что депозит открыт сразу после подачи заявки.             |
| R   | **Надёжность (Reliability)**           |              |
|     | Сервисы депозитного сценария, включая интернет-банк, должны работать 24/7 с доступностью не ниже 99,9%.                               | Текущая инфраструктура не подтверждает выполнение цели. Необходимо согласовать период измерения доступности, сроки восстановления и допустимую потерю данных, а также необходимые изменения инфраструктуры.             |
|     | При отказе основного ЦОД интернет-банк и компоненты нового процесса должны восстанавливать работу на резервной площадке с требуемой производительностью.                               |              |
| P   | **Производительность (Performance)**   |              |
|     | Просмотр каталога, получение ставок и подтверждение приёма заявки должны иметь минимальное время отклика при согласованной нагрузке.                               | Требование «за миллисекунды» необходимо уточнить числовыми порогами и процентилями. Время ручного согласования и доставки СМС следует измерять отдельно от отклика системы.             |
|     | Просмотр условий и подача онлайн-заявок не должны перегружать АБС или ухудшать выполнение основных банковских операций.                               
|              |Онлайн-компоненты нового процесса должны поддерживать горизонтальное масштабирование и распределение запросов между экземплярами и площадками с учётом выбранного режима работы ЦОД. АБС масштабируется только вертикально.
| S   | **Поддерживаемость (Supportability)**  |              |
|     | Необходимо подготовить документацию архитектуры, интеграционных интерфейсов, данных и бизнес-процесса для сопровождения и дальнейшего расширения системы.                               |              |
|     | Новый функционал следует по возможности разрабатывать и сопровождать силами банка через поддерживаемые механизмы расширения; доработки ядра интернет-банка подрядчиком желательно избежать.                             |              |
| +R  | **+ Ограничения (Restrictions)**       |              |
|     |  Предпочтительно использовать существующий стек банка: .NET/MS SQL, Delphi/Oracle, Java/PostgreSQL, PHP/React. Новые технологии должны быть совместимы с действующими платформами.                                |              |
|     | Передача чувствительных данных должна быть зашифрована. Совместная работа со ставками должна сохранять разграничение доступа: сотрудники депозитного и кредитного бэк-офиса не получают доступ к закрытым данным друг друга.                              |              |
